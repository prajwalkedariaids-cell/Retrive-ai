# RAG Chatbot (LangChain + Groq) with a web frontend

Chat with your own documents. Drop PDF, TXT, MD, DOCX or CSV files into the web UI,
then ask questions. Answers are generated by a Groq-hosted model, grounded in the
retrieved chunks, streamed live, and shown with their sources.

## Setup
```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env             # then put your Groq API key in .env
uvicorn main:app --reload
```
Open http://localhost:8000. (Interactive API docs: http://localhost:8000/docs)

You can also skip `.env` and paste the key into the sidebar of the UI.

## Folder layout
```
rag_chatbot/
├── main.py            # FastAPI backend: API routes + serves the frontend

├── static/
│   └── index.html     # Frontend (HTML/CSS/JS, no build step, no CDN)

├── .env.example       # copy to .env and add GROQ_API_KEY

```

## API
| Method | Path | Purpose |
|---|---|---|
| GET | `/api/config` | Models, supported file types, whether the server has a key |
| POST | `/api/upload` | Multipart: `session_id`, `files[]`, `chunk_size`, `chunk_overlap` |
| POST | `/api/chat` | JSON body; streams NDJSON events (`sources`, `token`, `error`, `done`) |
| GET | `/api/session/{id}` | Files and chat history for a session |
| DELETE | `/api/session/{id}/chat` | Clear chat |
| DELETE | `/api/session/{id}/documents` | Remove indexed documents |

## Notes
- Embeddings run locally (`all-MiniLM-L6-v2`); the first start downloads the model.
  Groq is used only for the chat model.
- Groq model names change: use the "custom model name" box in the sidebar if one is retired.
- Sessions and vector indexes live in server memory and reset when the server restarts.
  For multi-user or production use, add authentication and persist the index
  (e.g. `FAISS.save_local` or a database-backed vector store).
